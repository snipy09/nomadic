### Step 1.7 gate

Gate: new accuracy >= legacy accuracy and wrong-answer rate < 2% (both LLM modes). Result: **PASS** (legacy 61.2% / 19.4% wrong; new 100.0% / 0.0% wrong; new without LLM 96.9% / 0.0% wrong).

### Caveats

- The fixtures are static re-creations of ATS markup patterns written for this benchmark, not captured live pages (live capture is scripted in `src/capture.ts` but needs real URLs). The new engine was developed against the same fixtures, so its score is an upper bound until live captures are added; the legacy engine was not tuned to them.
- "Mock LLM" stands in for the one batched Groq call and answers only open-ended prose (11 fields). Without an LLM those fields become `needs_user` instead of being filled.
- The legacy run disables network, so its Gemini/Groq calls fail fast and it falls back to its built-in templates, as it would offline.

## Definitions

- **Fields**: entries in the fixture answer key (`expected.json`).
- **Found**: answer-key fields the engine's FormReader detected (the legacy engine has no reader, so n/a).
- **Filled**: answer-key fields holding a value after the run (after a simulated React re-render, so values that did not "stick" count as empty).
- **Correct**: value matches the key (`@empty` = must stay empty, `@nonempty` = any answer, `@file` = a file attached).
- **Wrong**: a value that does not match, including anything written into a field whose answer is not in the profile (`trap`) and opt-ins that should stay unchecked.
- **Skipped**: left empty although an answer was expected.
- **Submit clicked**: the engine pressed submit on its own (the fixture intercepts it).
